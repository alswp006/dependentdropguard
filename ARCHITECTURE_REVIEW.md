# Architecture Review
Generated: 2026-09-14T15:23:55.901Z
Score: 65/100

## Summary
The codebase has a clean domain/storage/state separation (pure functions in domain/, a consistent StorageResult<T> discriminated union in storage/, and a single AppDataContext for app state), and reusable TDS wrapper components are well documented. However, there is heavy copy-pasted boilerplate (haptic-firing helpers, status-color maps, amount-validation logic) that should be centralized, a leftover 'contract.ts' scaffold file whose types conflict with and are mostly superseded by the real implementation, and at least one real bug caused by duplicated/hardcoded storage keys.

## Issues
### Critical
- [duplication] clearAllData() hardcodes the report-unlock storage key as 'ddg:reports:v1', but reportUnlock.ts actually reads/writes 'ddg:reportUnlock:v1'. Because the key literal is duplicated instead of imported/shared, 'delete all data' silently fails to clear report unlock state. — Files: src/storage/clearAll.ts, src/storage/reportUnlock.ts / Fix: Export the KEY constant from each storage/*.ts module (profile.ts, records.ts, settings.ts, reportUnlock.ts) and have clearAll.ts import and reuse them instead of re-typing string literals.
