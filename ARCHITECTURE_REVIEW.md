# Architecture Review
Generated: 2026-09-13T22:57:20.897Z
Score: 70/100

## Summary
The app has a clean, consistent layered structure (domain/ for pure business logic, storage/ for persistence with a uniform StorageResult pattern, state/ for a single context, pages/ + components/ for UI), and no circular dependencies were found. The main weaknesses are heavy copy-paste duplication of small cross-cutting concerns (haptic feedback wrappers, status-color maps, amount validation constants) and a stale/half-dead 'contract.ts' scaffold whose types diverge from the real implementation, creating naming confusion (two incompatible 'RouteState' types).

## Issues
### Critical
- [naming] Two unrelated, incompatible types are both named `RouteState`: lib/contract.ts defines it as `{ page: ...; params? }` while types/navigation.ts defines it as a per-path state-shape map. Files import 'RouteState' from types/navigation while contract.ts's version is a different (seemingly unused) shape, which is highly confusing for anyone reading imports. — Files: src/lib/contract.ts, src/types/navigation.ts, src/pages/Home.tsx, src/pages/History.tsx, src/pages/Report.tsx, src/pages/Settings.tsx / Fix: Rename the contract.ts version (e.g. `LegacyRouteState` or remove it if unused) so the name `RouteState` is unique across the codebase.

- [duplication] The DiagnosisStatus → badge color mapping (SAFE/WARNING/DROP → green/yellow/red) is independently declared in three different files. — Files: src/pages/Home.tsx, src/pages/Report.tsx, src/components/simulate/CompareCard.tsx / Fix: Move STATUS_BADGE_COLOR into src/domain/rules.ts (next to STATUS_LABEL) and import it wherever needed.

### Suggestions
- [duplication] `amountError` (blank-string passthrough + validateAmount) is duplicated verbatim in Record.tsx and Simulate.tsx, and MAX_AMOUNT (1_000_000_000) plus its bounds-check logic is duplicated between lib/validation.ts and storage/records.ts. — Files: src/pages/Record.tsx, src/pages/Simulate.tsx, src/lib/validation.ts, src/storage/records.ts / Fix: Move amountError into lib/validation.ts and export it; have storage/records.ts import MAX_AMOUNT (or the validity check) from lib/validation.ts instead of redefining it.
- [naming] Inconsistent casing/suffix convention for function-type aliases in contract.ts: `JUDGMENT_RULESFn` uses SCREAMING_SNAKE_CASE+Fn while sibling types use camelCase+Fn (`formatCurrencyFn`, `diagnoseFn`, `simulateFn`, `saveMonthRecordFn`). — Files: src/lib/contract.ts / Fix: Rename to `judgmentRulesFn` for consistency with the rest of the file.
- [dead_code] `lib/utils.ts` exports `cn` and `formatCurrency`, neither of which appears to be imported by any component (components pass raw style objects, and utils/format.ts's `formatWon` is used instead for currency display). — Files: src/lib/utils.ts, src/utils/format.ts / Fix: Remove `cn`/`formatCurrency` if truly unused, or consolidate all number/currency formatting into a single utils/format.ts module to avoid two competing formatting utilities (lib/utils.ts vs utils/format.ts).
- [dead_code] domain/simulation.ts re-exports `computeSimulation` under the alias `simulate` solely to satisfy contract.ts's `simulateFn`, but callers (Simulate.tsx) use `computeSimulation` directly, leaving the `simulate` export unused. — Files: src/domain/simulation.ts, src/pages/Simulate.tsx / Fix: Drop the alias export once contract.ts is cleaned up, or standardize call sites on one name.
- [dead_code] types/navigation.ts exports standalone state-union types (HomeState, ProfileState, RecordState, HistoryState, ReportState, SimulateState) but pages consume them via the `RouteState['/path']` indexed form instead, so the standalone named exports look unreferenced. — Files: src/types/navigation.ts, src/pages/Home.tsx, src/pages/Profile.tsx / Fix: Verify usage with a references search; if unused, remove the standalone aliases and keep only the RouteState map, or conversely use the named aliases consistently instead of indexed lookups.
- [structure] ReportUnlockManager.tsx lives in src/pages/ even though it's a reusable UI component (ad-gate) rather than a routed page, breaking the otherwise consistent pattern of feature components living under components/<feature>/. — Files: src/pages/ReportUnlockManager.tsx, src/components/home/ReminderBanner.tsx, src/components/record/StatusChangeDialog.tsx / Fix: Move it to src/components/report/ReportUnlockManager.tsx to match the home/record/settings/simulate component grouping convention.
- [consistency] Amount.tsx and CountUp.tsx duplicate the exact same wrapper `<span>` style object (display, maxWidth, whiteSpace: nowrap, tabular-nums) for rendering a formatted number, differing only in whether the value animates. — Files: src/components/Amount.tsx, src/components/CountUp.tsx / Fix: Extract the shared nowrap/tabular-nums span into a small internal `NumericText` wrapper used by both Amount and CountUp.
